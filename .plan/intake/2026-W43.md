**What was fixed, and why** (the three sentences the rule asks for, for each):

* *Six contract tests that were red when the beta gate was last assessed.* They are green: `python3 -m pytest
  tests/test_cli_contract.py::… tests/test_config_contract.py::… tests/test_risk_ranking_contract.py::…
  tests/test_segmentation_spike_contract.py::… tests/test_workspace_contract.py::test_lint_subcommand_is_clean_on_the_repo_root`
  → `6 passed in 10.00s` against the binary built from this tree. The cause was drift, not breakage — each
  of the six asserts a cross-artefact agreement (a document naming a degraded state, a config key the schema
  knows, a lint set clippy agrees with) and each had been left behind by the ticket that moved the thing it
  watches. Closed here because the beta gate had been quoting them as red; they were fixed by the tickets
  that moved the contracts, not by this one.
* *Five shipped commits with no trace in the changelog.* The release body is the changelog, so a ticket that
  lands without an entry is a ticket nobody hears about; the fix is `tools/gen_changelog.py` — an `audit`
  that reads every commit since the last cut and refuses the next cut until the notes account for each one. The
  five are now named in `CHANGELOG.md` (`e3.7`, `e7.1`, `e5.6`, `e7.8` and the `s3` storage correction),
  and `.plan/changelog-coverage.json` stays **empty** on purpose: an exemption is for an omission a
  human has accepted with a reason and an owner, and `C07` fails the next cut if a covered exemption
  is left in it.

* *The three queue-screen tests that were red, and the stale list that hid them.* They are green, and the
  queue was never the problem: on the 500-commit fixture it draws 27 ranked rows on the first screen. The
  harness was reading the pty after it went quiet, which on a cold TUI is before it has painted anything, so
  the sample was a blank screen and the assertion called it an empty queue (`reco-2vq`; the fix and the test
  that pins the distinction are in `tests/test_risk_ranking_contract.py`). Why it is in this register at all:
  the gate's known-red list named two *other* tests in that file, both green, which is what a known-red list
  becomes when nobody re-runs it — the red moved and the page did not. The whole suite was re-run for the
  re-record (`python3 -m pytest -q`: 2,141 tests, one red), that red is **W43-30** / **reco-0ip**, and
  `.plan/beta-gate-reco-69u.md` §2 now carries the current list.

* *The finding that named an episode no verb could read.* The sentence carried the first twelve characters of
  a twenty-three-character id while the finding's own `index:episode …` evidence carried the whole of it, so
  the reviewer who typed what the gate printed got `cannot resolve`. Both episode-shaped checks print the
  whole id, in the sentence and in the evidence, from one binding per finding, and the `fix:` line names
  `fathom analyze <episode>` and `fathom review sign <episode>`, both of which read it; a test now resolves
  every `ep-…` a `check --format json` run prints (**W43-35** / **reco-dvu**).

* *The config key that configured nothing, in the product's own config.* A weight named for an axis the vector
  has never carried, noticed only in the last three lines of a score nobody re-reads,
  and validated as clean by the only checker that looks at the file — because `[risk.weights]` is an open map
  in the key spec and a name inside it is not the schema's to judge. The vector refuses it where it is read, and
  `fathom doctor` now prints that refusal by itself, once, as the untidy finding `config_ignored_key` with its
  remedy and exit `5` under `--strict`; the dead line is gone from this repository's `fathom.toml`, and the
  reader that refuses it runs over this file in a test so the next one is CI-red (**W43-36** / **reco-gna**).

  the tree it was written against", which is a claim that can be true. `tests/test_beta_loop_contract.py` is
  27 passed and the suite's known-red list in `.plan/beta-gate-reco-69u.md` §2 is empty (`reco-0ip`).
