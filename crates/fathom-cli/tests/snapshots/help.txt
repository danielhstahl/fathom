===== fathom --help =====
Review an agent-driven repository before it merges.

Usage: fathom [OPTIONS] [COMMAND]

Commands:
  index         Index the repository so every other verb has something to read
  show          Show one episode in full
  episodes      List the episodes — the rail's rows, headless (`reco-11b`)
  attribution   Report or correct who Fathom thinks wrote a commit (`e4.1`)
  review        The review ledger: sign-offs that outlive the history they were written about (`e4.6`)
  analyze       Print one episode's delta document — the model the TUI, the export and an agent all read
  narrative     Read one episode: the narrative every claim in it cites its evidence from (`e4.7`)
  drift         What the plan said against what the session did — the contradictions, both sides linked (`e4.8`)
  why           Print one episode's risk score with every feature, its weight and its contribution (`e4.4`)
  stats         Report repo scale, index state and cache hit rate
  check         Run the checks CI cares about; findings above the threshold exit 7
  doctor        Describe this build, its environment and its index, with a remedy per finding
  export        Write a review artefact for a pull request or an audit
  mcp           Speak MCP to a coding agent
  watch         Watch the repository and index as it changes
  ambient       The glance pane for the terminal beside the agent: latest episode, queue, index, one reason (`reco-8bx`)
  hooks         Report on the harness event stream: lag, offset, rejections, replay (`e6.1`)
  daemon        The one process per repository that watches, tails the harness stream and indexes (`e6.3`)
  status        Who is keeping this index current, what it costs, and what is left (`e6.3`)
  tui           Print the terminal UI's keymap, or open the UI itself
  open          Open an episode's file at its line in `$EDITOR` — jump out, do not read around it (`e5.8`)
  difftool      Show one file's two sides in your own difftool — difftastic, meld, kdiff3, `vim -d` (`e5.8`)
  cmp           Compare any two episodes or revisions: the composed delta over a range (`e5.3`)
  search        Search the whole index from one box, in the shell's own ranking (`e5.2`)
  architecture  The architecture scorecard: five dimensions, one number, and the drift since your last review (`e3.9`)
  ratchet       The ratchet: the committed allowance ledger, which tightens on its own and widens only when told to (`e3.10`)
  context       What this repository knows about a path or an episode: the recorded decisions and the open questions (`e6.5`)
  note          The review memory: notes, decisions, questions and follow-ups, committed under `.fathom/reviews/` (`e6.5`)
  completions   Print the shell's own copy of this grammar: completion scripts and man pages (`e7.4`)
  events        Read the analysis event stream a run wrote: what happened, in order (`e6.7`)
  help          Print this message or the help of the given subcommand(s)

Options:
      --plain
          Draw as text, with no terminal taken: for pipes, CI logs and screen readers (ADR-006 §6.7).
          
          Chosen automatically when stdout is not a terminal, so a redirected run degrades by itself.

      --no-alt-screen
          Draw in place instead of taking the alternate screen, which keeps the shell's scrollback

      --fresh
          Ignore the session this repository has stored, and start from defaults (`e1.11`).
          
          The escape hatch for a session that came back wrong: a filter that hides the episode you are looking for, a cursor on a row that moved. The stored state is not destroyed — a run that changes nothing writes nothing — it is simply not applied to this one.

      --mouse
          Take the mouse: click selects, double-click drills, the wheel scrolls (`e5.5`, ADR-006 §10.1).
          
          Off by default, because capturing the pointer takes the terminal's own text selection away for the length of the run. Every gesture it adds is also a key, and the status line says `mouse on` while it is armed.

      --lines
          With `--plain`: print the frame in reading order, one block per pane, instead of side by side.
          
          Two panes drawn next to each other is the right shape for eyes and the wrong shape for a log, a pipe or a screen reader (ADR-006 §6.7). Same facts, same order, one per line.

      --theme <NAME|PATH>
          Paint the frame with this theme: a built-in name, a theme file, or a path to one (`e5.6`).
          
          `dark`, `light` and `ansi` are built in, and all three are measured — for contrast against the background they paint, and for how far the added / removed / violation pairs stay apart when protanopia and deuteranopia are simulated. Anything else is `<name>.toml` in `$FATHOM_THEME_DIR` or `~/.config/fathom/themes/`, or a path. `$FATHOM_THEME` and `[theme] name` in your own config are the same knob one layer down; a repository's `fathom.toml` is deliberately not a layer at all, because a clone does not get to repaint your terminal. With colour off — `NO_COLOR`, or a terminal that has none — the theme is not applied and every state keeps its shape and its word. `fathom tui --list-themes` lists what Fathom can see; `--show-theme` prints the one in force with its measurements, and `--show-theme --audit` exits 7 if a palette fails a floor.

      --demo
          Review a miniature repository that ships inside this binary, then say what to do next (`e5.9`).
          
          The five-minute tour: Fathom unpacks a 21-commit repository into its cache directory, indexes it with the same `fathom index` you would run on your own history, and opens on it. Nothing in the directory you ran it from is read or written, no configuration is read, and deleting `$XDG_CACHE_HOME/fathom` is a complete undo. With a verb the verb runs against the miniature; with none you get the shell.

      --progress
          Print the index's progress row even where stderr is not a terminal (`e5.9`).
          
          On a terminal the row is on by default, one row overwriting itself; this asks for it in a log, a CI step or a `watch -n 1` wrapper, where one line per update is the point. It applies to `fathom index` and to the indexing `fathom --demo` does on your behalf — no other verb has a row to print — and `--json` refuses it, because that stream belongs to the run report and a row beside a machine-readable document is how a parser dies.

      --no-progress
          Never print the index's progress row, even on a terminal (`e5.9`).
          
          The other half of the same choice: a script with its own progress line, or a run whose output is being tee'd somewhere, turns it off explicitly instead of discovering it on.

      --no-watch
          Do not watch the repository from an open frame: show what the index holds, and say so (`reco-bpc`).
          
          An open shell watches its repository by default, so a commit made in another terminal arrives by itself. This turns that off, and the frame then says `snapshot` and what would move it rather than letting a still rail be read as a quiet repository. The other way to get the same picture, cheaper, is to run `fathom watch` in a second terminal and let it own the indexing.

      --detectors <SPEC>
          Which detectors run, moved off the file's answer (`e6.7`).
          
          A comma-separated spec: `id` or `+id` runs one as well, `-id` turns one off even if it ships on, `all` bases the set on every built-in detector, and `none` bases it on nothing. So `--detectors none,+churn_loop` is one detector and `--detectors all,-secret_string` is eleven. It is the same grammar as `detectors.enabled` and `detectors.disable` in `fathom.toml`, applied after it, and it names a plugin detector by its namespaced id (`--detectors +acme.untested_agent_logic`). A `--detectors` line is what a CI job uses to ask one narrow question without editing a file.

      --enable-detector <ID>
          Run one more detector, by id — the long form of `--detectors +id` (`e6.7`)

      --disable-detector <ID>
          Do not run one detector, by id — the long form of `--detectors -id` (`e6.7`).
          
          This is the switch for a built-in you have decided about: the row stays in the report as `disabled`, so "did it look?" still has an answer, and `detectors.suppress` stays the switch for a finding whose family you have muted rather than a detector you have turned off.

      --events <FILE>
          Write this run's analysis event stream to a file, or to stderr with `-` (`e6.7`).
          
          One JSON object per line, versioned, appended: what started, what each detector did, what every finding said, and how the run ended. `[events] enabled = true` turns the stream on for a repository; this turns it on for one run, over whatever the file says. `fathom events` reads it back.

  -h, --help
          Print help (see a summary with '-h')

  -V, --version
          Print version

===== fathom index --help =====
Index the repository so every other verb has something to read

Usage: fathom index [OPTIONS] [ROOT]

Arguments:
  [ROOT]
          The repository to index
          
          [default: .]

Options:
      --plain
          Draw as text, with no terminal taken: for pipes, CI logs and screen readers (ADR-006 §6.7).
          
          Chosen automatically when stdout is not a terminal, so a redirected run degrades by itself.

      --stats
          Print the per-analyzer cache table (ADR-004 §4.8)

      --json
          Print the run report as JSON on stdout, and nothing else there

      --no-alt-screen
          Draw in place instead of taking the alternate screen, which keeps the shell's scrollback

      --fresh
          Ignore the session this repository has stored, and start from defaults (`e1.11`).
          
          The escape hatch for a session that came back wrong: a filter that hides the episode you are looking for, a cursor on a row that moved. The stored state is not destroyed — a run that changes nothing writes nothing — it is simply not applied to this one.

      --refresh
          Look up every stored unit, and recompute the ones that hit too.
          
          This is the pass that *measures* ADR-004 §6's invalidation matrix instead of trusting it: after a version or config bump it prints exactly the rows that moved, and after an unremarkable commit it prints 100% hits.

      --mouse
          Take the mouse: click selects, double-click drills, the wheel scrolls (`e5.5`, ADR-006 §10.1).
          
          Off by default, because capturing the pointer takes the terminal's own text selection away for the length of the run. Every gesture it adds is also a key, and the status line says `mouse on` while it is armed.

      --rebuild
          Throw the epoch away and rebuild every analysis from scratch.
          
          The old epoch's rows stay on disk and are marked dead (ADR-004 §6.3), so a rebuild that is interrupted is recoverable by definition; the staging file and atomic swap of §9.3 arrive with the daemon that has a concurrent reader to protect.

      --lines
          With `--plain`: print the frame in reading order, one block per pane, instead of side by side.
          
          Two panes drawn next to each other is the right shape for eyes and the wrong shape for a log, a pipe or a screen reader (ADR-006 §6.7). Same facts, same order, one per line.

      --watch
          Index once, then keep watching and index as the repository changes.
          
          The one-shot form a script wants, and the same thing as `fathom watch` with an initial index.

      --committed-only
          Do not analyse uncommitted paths (ADR-004 §6.4)

      --theme <NAME|PATH>
          Paint the frame with this theme: a built-in name, a theme file, or a path to one (`e5.6`).
          
          `dark`, `light` and `ansi` are built in, and all three are measured — for contrast against the background they paint, and for how far the added / removed / violation pairs stay apart when protanopia and deuteranopia are simulated.       --prune
          Remove the commit rows no ref can reach — what a rebase, an `--amend` or a force-push leaves behind.
          
          The only verb that deletes anything (ADR-004 §8.1). It runs after this run, against the ref tips this run just read, and it refuses rather than guesses: rows the store cannot prove are dead stay, and so does any row a review or a sign-off points at. `fathom stats` prints the count and names this flag.

      --no-graph
          Do not write the module graph (`e3.11`).
          
          The escape hatch for a run that cannot afford it: one revision's graph costs one structural pass over its live source corpus, which is the expensive thing this index does. `[graph] enabled = false` in the repository's own `fathom.toml` is the durable form of the same refusal, and `graph.window` / `graph.max_corpus_mib` are the knobs that make it affordable instead of off. With either, the architecture surfaces say they have no graph rather than guessing without one.

      --progress
          Print the index's progress row even where stderr is not a terminal (`e5.9`).
          
          On a terminal the row is on by default, one row overwriting itself; this asks for it in a log, a CI step or a `watch -n 1` wrapper, where one line per update is the point. It applies to `fathom index` and to the indexing `fathom --demo` does on your behalf — no other verb has a row to print — and `--json` refuses it, because that stream belongs to the run report and a row beside a machine-readable document is how a parser dies.

      --dry-run
          With `--prune`: print what would be removed and remove nothing

      --no-progress
          Never print the index's progress row, even on a terminal (`e5.9`).
          
          The other half of the same choice: a script with its own progress line, or a run whose output is being tee'd somewhere, turns it off explicitly instead of discovering it on.

      --no-watch
          Do not watch the repository from an open frame: show what the index holds, and say so (`reco-bpc`).
          
          An open shell watches its repository by default, so a commit made in another terminal arrives by itself. This turns that off, and the frame then says `snapshot` and what would move it rather than letting a still rail be read as a quiet repository. The other way to get the same picture, cheaper, is to run `fathom watch` in a second terminal and let it own the indexing.

      --detectors <SPEC>
          Which detectors run, moved off the file's answer (`e6.7`).
          
          A comma-separated spec: `id` or `+id` runs one as well, `-id` turns one off even if it ships on, `all` bases the set on every built-in detector, and `none` bases it on nothing. So `--detectors none,+churn_loop` is one detector and `--detectors all,-secret_string` is eleven. It is the same grammar as `detectors.enabled` and `detectors.disable` in `fathom.toml`, applied after it, and it names a plugin detector by its namespaced id (`--detectors +acme.untested_agent_logic`). A `--detectors` line is what a CI job uses to ask one narrow question without editing a file.

      --enable-detector <ID>
          Run one more detector, by id — the long form of `--detectors +id` (`e6.7`)

      --disable-detector <ID>

          Print help (see a summary with '-h')

  -V, --version
          Print version

===== fathom episodes --help =====
List the episodes — the rail's rows, headless (`reco-11b`)

Usage: fathom episodes [OPTIONS]

Options:
      --plain
          Draw as text, with no terminal taken: for pipes, CI logs and screen readers (ADR-006 §6.7).
          
          Chosen automatically when stdout is not a terminal, so a redirected run degrades by itself.

      --root <ROOT>
          The repository to read
          
          [default: .]

      --json
          Print the list as one JSON value on stdout (`fathom.cli.episodes/1`), and nothing else there

      --no-alt-screen
          Draw in place instead of taking the alternate screen, which keeps the shell's scrollback

      --fresh
          Ignore the session this repository has stored, and start from defaults (`e1.11`).
          
          The escape hatch for a session that came back wrong: a filter that hides the episode you are looking for, a cursor on a row that moved. The stored state is not destroyed — a run that changes nothing writes nothing — it is simply not applied to this one.

      --limit <N>
          How many rows to print, newest first; `0` is every row the filters select.
          
          The rail can only ever hold 500 rows at a time; this verb is not a rail, so a larger page is allowed, and `page.truncated` says when the index held more than the page.
          
          [default: 500]

      --mouse
          Take the mouse: click selects, double-click drills, the wheel scrolls (`e5.5`, ADR-006 §10.1).

      --offset <N>

          [default: 0]

      --author <NAME>
          Only episodes by this author, exactly as git recorded the name; repeatable

      --lines
          With `--plain`: print the frame in reading order, one block per pane, instead of side by side.
          
          Two panes drawn next to each other is the right shape for eyes and the wrong shape for a log, a pipe or a screen reader (ADR-006 §6.7). Same facts, same order, one per line.

===== fathom review --help =====
The review ledger: sign-offs that outlive the history they were written about (`e4.6`)

Usage: fathom review [OPTIONS] [COMMAND]

Commands:
  status  The verdict: is every episode covered by a sign-off that still matches (exit `7` when it is not)

  help    Print this message or the help of the given subcommand(s)

Options:
      --plain

      --root <ROOT>
          The repository to read
          
          [default: .]

      --json
          Print the verdict and every entry as one JSON line (machine contract `fathom.cli.review/1`).

      --no-alt-screen
          Draw in place instead of taking the alternate screen, which keeps the shell's scrollback

      --fresh
          Ignore the session this repository has stored, and start from defaults (`e1.11`).
          
          The escape hatch for a session that came back wrong: a filter that hides the episode you are looking for, a cursor on a row that moved. The stored state is not destroyed — a run that changes nothing writes nothing — it is simply not applied to this one.

      --mouse
          Take the mouse: click selects, double-click drills, the wheel scrolls (`e5.5`, ADR-006 §10.1).
          
          Off by default, because capturing the pointer takes the terminal's own text selection away for the length of the run. Every gesture it adds is also a key, and the status line says `mouse on` while it is armed.

      --lines
          With `--plain`: print the frame in reading order, one block per pane, instead of side by side.
          
          Two panes drawn next to each other is the right shape for eyes and the wrong shape for a log, a pipe or a screen reader (ADR-006 §6.7). Same facts, same order, one per line.

      --theme <NAME|PATH>
          Paint the frame with this theme: a built-in name, a theme file, or a path to one (`e5.6`).
          
          `dark`, `light` and `ansi` are built in, and all three are measured — for contrast against the background they paint, and for how far the added / removed / violation pairs stay apart when protanopia and deuteranopia are simulated. Anything else is `<name>.toml` in `$FATHOM_THEME_DIR` or `~/.config/fathom/themes/`, or a path. `$FATHOM_THEME` and `[theme] name` in your own config are the same knob one layer down; a repository's `fathom.toml` is deliberately not a layer at all, because a clone does not get to repaint your terminal. With colour off — `NO_COLOR`, or a terminal that has none — the theme is not applied and every state keeps its shape and its word. `fathom tui --list-themes` lists what Fathom can see; `--show-theme` prints the one in force with its measurements, and `--show-theme --audit` exits 7 if a palette fails a floor.

      --progress
          Print the index's progress row even where stderr is not a terminal (`e5.9`).
          
          On a terminal the row is on by default, one row overwriting itself; this asks for it in a log, a CI step or a `watch -n 1` wrapper, where one line per update is the point. It applies to `fathom index` and to the indexing `fathom --demo` does on your behalf — no other verb has a row to print — and `--json` refuses it, because that stream belongs to the run report and a row beside a machine-readable document is how a parser dies.

      --no-progress
          Never print the index's progress row, even on a terminal (`e5.9`).
          
          The other half of the same choice: a script with its own progress line, or a run whose output is being tee'd somewhere, turns it off explicitly instead of discovering it on.

      --no-watch
          Do not watch the repository from an open frame: show what the index holds, and say so (`reco-bpc`).
          
          An open shell watches its repository by default, so a commit made in another terminal arrives by itself. This turns that off, and the frame then says `snapshot` and what would move it rather than letting a still rail be read as a quiet repository. The other way to get the same picture, cheaper, is to run `fathom watch` in a second terminal and let it own the indexing.

      --detectors <SPEC>
          Which detectors run, moved off the file's answer (`e6.7`).
          
          A comma-separated spec: `id` or `+id` runs one as well, `-id` turns one off even if it ships on, `all` bases the set on every built-in detector, and `none` bases it on nothing. So `--detectors none,+churn_loop` is one detector and `--detectors all,-secret_string` is eleven. It is the same grammar as `detectors.enabled` and `detectors.disable` in `fathom.toml`, applied after it, and it names a plugin detector by its namespaced id (`--detectors +acme.untested_agent_logic`). A `--detectors` line is what a CI job uses to ask one narrow question without editing a file.

      --enable-detector <ID>
          Run one more detector, by id — the long form of `--detectors +id` (`e6.7`)

      --disable-detector <ID>
          Do not run one detector, by id — the long form of `--detectors -id` (`e6.7`).
          
          This is the switch for a built-in you have decided about: the row stays in the report as `disabled`, so "did it look?" still has an answer, and `detectors.suppress` stays the switch for a finding whose family you have muted rather than a detector you have turned off.

      --events <FILE>
          Write this run's analysis event stream to a file, or to stderr with `-` (`e6.7`).
          
          One JSON object per line, versioned, appended: what started, what each detector did, what every finding said, and how the run ended. `[events] enabled = true` turns the stream on for a repository; this turns it on for one run, over whatever the file says. `fathom events` reads it back.

          Write this run's analysis event stream to a file, or to stderr with `-` (`e6.7`).
          
          One JSON object per line, versioned, appended: what started, what each detector did, what every finding said, and how the run ended. `[events] enabled = true` turns the stream on for a repository; this turns it on for one run, over whatever the file says. `fathom events` reads it back.

  -h, --help
          Print help (see a summary with '-h')

  -V, --version
          Print version
